## 1. 项目概述

| 项目名称 | boatman-health-server |
| --- | --- |
| 技术栈 | Express + Prisma + TypeScript + SQLite |
| 入口文件 | `dist/app.js`（编译后） |
| 生产端口 | 3001 |
| 测试端口 | 3003 |
| 数据库 | SQLite（文件型，零配置） |
| 外部集成 | 飞书多维表格（表单数据同步） |

### 项目结构

```
server/
├── prisma/
│   ├── schema.prisma          # 数据库模型定义
│   ├── migrations/            # 数据库迁移文件
│   └── dev.db                 # SQLite 数据库文件
├── src/                       # TypeScript 源码
│   ├── app.ts                 # 应用入口
│   ├── config/                # 配置（env、database、feishu）
│   ├── controllers/           # 控制器
│   ├── middleware/             # 中间件（auth、errorHandler、validator）
│   ├── models/                # 类型定义
│   ├── routes/                # 路由
│   ├── services/              # 业务逻辑
│   └── utils/                 # 工具函数
├── dist/                      # 编译输出（部署用）
├── .env                       # 环境变量（不提交 Git）
├── .env.example               # 环境变量示例
├── package.json
└── tsconfig.json
```

### API 路由

| 路由前缀 | 功能 |
| --- | --- |
| `/api/auth` | 用户认证（注册/登录/短信验证码） |
| `/api/form1` | 表单1 — 咨询预约 |
| `/api/form2` | 表单2 — 健康评估 |
| `/admin` | 管理后台（需 admin 角色） |
| `/health` | 健康检查端点 |

## 4. 本地打包上传

### 4.1 本地编译

在本地 `server/` 目录下执行：

```bash
cd server

# 安装依赖
npm install

# 生成 Prisma Client
npx prisma generate

# TypeScript 编译
npm run build
```

编译成功后会在 `dist/` 目录生成 JavaScript 文件。

### 4.2 打包（排除 node_modules）

**方式一：在 `server/` 目录内执行（推荐）**

```bash
cd server
tar -cf ../server-deploy.tar --exclude="node_modules" --exclude=".env" --exclude="*.db" --exclude="*.db-journal" .
```

**方式二：在项目根目录执行**

```bash
tar -cf server-deploy.tar --exclude="node_modules" --exclude=".env" --exclude="*.db" --exclude="*.db-journal" -C server .
```

> **Windows PowerShell** 同样支持 `tar` 命令，语法一致。

### 4.3 验证打包内容（重要）

打包后务必检查 `prisma/` 目录是否包含在内：

```bash
tar -tf server-deploy.tar | grep prisma
```

应看到类似输出：

```
./prisma/
./prisma/schema.prisma
./prisma/migrations/
./prisma/migrations/20xxxxxx_init/
./prisma/migrations/20xxxxxx_init/migration.sql
...
```

> ⚠️ 如果看不到 `prisma/schema.prisma`，说明打包路径有误，**请勿继续上传**，先修正打包命令。

打包内容应包含：
- `dist/` — 编译后的 JS 文件（运行时需要）
- `prisma/schema.prisma` — Prisma 数据库模型定义（**必须包含**）
- `prisma/migrations/` — 数据库迁移文件（**必须包含**）
- `package.json` + `package-lock.json` — 依赖信息
- `tsconfig.json` — TypeScript 配置
- `.env.example` — 环境变量模板

### 4.4 上传到服务器

```bash
scp server-deploy.tar root@<服务器IP>:/opt/boatman-health-A4-server/
# 示例：scp server-deploy.tar root@118.145.239.169:/opt/boatman-health-A4-server/
```

## 5. 服务器端部署

### 5.1 解压文件

```bash
cd /opt/boatman-health-A4-server
tar -xf server-deploy.tar
rm server-deploy.tar   # 清理压缩包
```

### 5.2 安装生产依赖

```bash
npm install --production
```

> 仅安装 `dependencies`，不安装 `devDependencies`（如 TypeScript 编译器），节省空间。

### 5.3 安装 Prisma CLI

`prisma` CLI 位于 `devDependencies`，生产安装不会包含它，但 `prisma generate` 和 `prisma migrate deploy` 命令需要它。单独安装：

```bash
npm install prisma --save-dev
```

> 或者如果不想写入 `package.json`，也可以直接用 `npx prisma`（npx 会自动下载缺失的包）。

### 5.4 生成 Prisma Client

```bash
npx prisma generate --schema=./prisma/schema.prisma
```

> 这一步在服务器上必须执行，因为 Prisma Client 会根据当前操作系统生成平台特定的查询引擎。
> 显式指定 `--schema` 路径可以避免 Prisma 找不到 Schema 文件的问题。

## 6. 环境变量配置

### 6.1 创建 .env 文件

```bash
cd /opt/boatman-health-A4-server
cp .env.example .env
nano .env
```

### 6.2 生产环境 .env 配置

```env
# 数据库（SQLite 文件路径，相对于 prisma 目录）
DATABASE_URL=file:./prod.db

# JWT 密钥（务必替换为随机复杂字符串，32 位以上）
JWT_SECRET=<你的随机密钥>

# 服务端口
PORT=3000

# 飞书集成
FEISHU_APP_ID=<你的飞书APP_ID>
FEISHU_APP_SECRET=<你的飞书APP_SECRET>

# 表单1 飞书多维表格（咨询表单）
FORM1_APP_TOKEN=<你的多维表格TOKEN>
FORM1_TABLE_ID=<你的表格TABLE_ID>

# 表单2 飞书多维表格（健康评估表单）
FORM2_APP_TOKEN=<你的多维表格TOKEN>
FORM2_TABLE_ID=<你的表格TABLE_ID>

# 生产模式（关闭固定验证码等开发特性）
NODE_ENV=production
```

### 6.3 生成随机 JWT 密钥

```bash
# 使用 openssl 生成 64 位随机密钥
openssl rand -hex 32
```

将输出复制到 `.env` 文件的 `JWT_SECRET` 字段。

### 6.4 保存退出

在 nano 编辑器中：
- `Ctrl + O` → 保存
- `Enter` → 确认文件名
- `Ctrl + X` → 退出

## 7. 数据库初始化

### 7.1 执行数据库迁移

```bash
cd /opt/boatman-health-A4-server
npx prisma migrate deploy --schema=./prisma/schema.prisma
```

该命令会：
- 读取 `prisma/migrations/` 中的迁移文件
- 在 `prisma/` 目录下创建 `prod.db`（由 `DATABASE_URL` 指定）
- 创建所有数据库表（`users`、`form1_submissions`、`form2_submissions`）

> **注意**：显式指定 `--schema=./prisma/schema.prisma` 可以避免 `Could not find Prisma Schema` 错误。确保当前工作目录为 `/opt/boatman-health-A4-server`。

### 7.2 验证数据库

```bash
# 检查数据库文件是否创建成功
ls -la prisma/prod.db
```

> ⚠️ **注意**：不要将 `dev.db`（开发数据库）上传到生产环境。生产环境应通过迁移创建全新的数据库。

## 8. PM2 进程守护

### 8.1 使用 PM2 启动服务

```bash
cd /opt/boatman-health-A4-server
pm2 start dist/app.js --name boatman-health-A4
```

### 8.2 验证服务运行

```bash
# 查看 PM2 进程列表
pm2 list

# 查看实时日志
pm2 logs boatman-health-A4

# 测试健康检查端点
curl http://localhost:3001/health
# 应返回：{"status":"ok","timestamp":"..."}
```

### 8.3 配置开机自启

```bash
pm2 startup
# 按提示执行输出的命令，例如：
# sudo env PATH=$PATH:/home/user/.nvm/versions/node/v20.x.x/bin pm2 startup systemd -u root --hp /root

pm2 save
```

### 8.4 PM2 生态配置文件（推荐）

创建 `ecosystem.config.js`，方便管理：

```bash
nano /opt/boatman-health-A4-server/ecosystem.config.js
```

内容：

```javascript
module.exports = {
  apps: [{
    name: 'boatman-health-A4',
    script: 'dist/app.js',
    cwd: '/opt/boatman-health-A4-server',
    instances: 1,
    autorestart: true,
    watch: false,
    max_memory_restart: '500M',
    env: {
      NODE_ENV: 'production'
    },
    error_file: '/opt/boatman-health-A4-server/logs/error.log',
    out_file: '/opt/boatman-health-A4-server/logs/output.log',
    log_date_format: 'YYYY-MM-DD HH:mm:ss'
  }]
};
```

使用配置文件启动：

```bash
mkdir -p /opt/boatman-health-A4-server/logs
pm2 start ecosystem.config.js
pm2 save
```

## 9. Nginx 反向代理（可选）

如果需要通过域名或 80/443 端口访问，配置 Nginx 反向代理。

### 9.1 安装 Nginx

```bash
sudo apt update
sudo apt install nginx -y
```

### 9.2 配置反向代理

```bash
sudo nano /etc/nginx/sites-available/boatman-health-A4
```

内容：

```nginx
server {
    listen 80;
    server_name <你的域名或公网IP>;

    # API 请求代理到 Node.js
    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

### 9.3 启用配置

```bash
sudo ln -s /etc/nginx/sites-available/boatman-health-A4 /etc/nginx/sites-enabled/
sudo nginx -t           # 检查配置语法
sudo systemctl reload nginx
```

### 9.4 配置 HTTPS（推荐）

使用 Let's Encrypt 免费证书：

```bash
sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d <你的域名>
```

## 10. 防火墙与安全组

### 10.1 腾讯云安全组

在腾讯云控制台 → 轻量应用服务器 → 防火墙，添加以下规则：

| 协议 | 端口 | 来源 | 说明 |
| --- | --- | --- | --- |
| TCP | 22 | 0.0.0.0/0 | SSH 登录 |
| TCP | 80 | 0.0.0.0/0 | HTTP 访问（使用 Nginx 时） |
| TCP | 443 | 0.0.0.0/0 | HTTPS 访问（使用 Nginx 时） |
| TCP | 3000 | 0.0.0.0/0 | Node.js 直接访问（不使用 Nginx 时） |

> ⚠️ 如果使用 Nginx 反向代理，建议**不开放** 3000 端口，仅通过 Nginx 的 80/443 端口访问。

### 10.2 服务器 UFW 防火墙（可选）

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# 如果不使用 Nginx，开放 3000
# sudo ufw allow 3000/tcp
sudo ufw enable
sudo ufw status
```

## 12. 常见问题排查

### Q1: `Could not find Prisma Schema`

**原因**：`prisma/schema.prisma` 文件缺失。

**解决**：确保打包时包含了 `prisma/` 目录。如果遗漏，单独上传：

```bash
# 本地
tar -cf prisma.tar -C server prisma/
scp prisma.tar root@<服务器IP>:/opt/boatman-health-A4-server/

# 服务器
cd /opt/boatman-health-A4-server
tar -xf prisma.tar
rm prisma.tar
npx prisma generate
npx prisma migrate deploy
```

### Q2: `Error: P1001 Can't reach database server`

**原因**：`DATABASE_URL` 配置不正确。

**解决**：确认 `.env` 中 `DATABASE_URL=file:./prod.db`，路径相对于 `prisma/` 目录。

### Q3: 服务启动后立即退出

**排查步骤**：

```bash
# 1. 查看错误日志
pm2 logs boatman-health-A4 --err

# 2. 手动运行查看报错
cd /opt/boatman-health-A4-server
node dist/app.js

# 3. 常见原因
# - .env 文件缺失或配置错误
# - node_modules 未安装
# - prisma client 未生成（运行 npx prisma generate）
# - 端口被占用（netstat -tlnp | grep 3000）
```

### Q4: 端口被占用

```bash
# 查看占用端口的进程
lsof -i :3001
# 或
netstat -tlnp | grep 3000

# 终止占用进程
kill -9 <PID>
```

### Q5: 飞书数据同步失败

**排查**：

```bash
# 检查飞书配置
cat .env | grep FEISHU

# 测试飞书 API 连通性
curl -X POST https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal \
  -H 'Content-Type: application/json' \
  -d '{"app_id":"<FEISHU_APP_ID>","app_secret":"<FEISHU_APP_SECRET>"}'
```

如果返回 `tenant_access_token`，说明飞书配置正确。

### Q6: 内存不足

```bash
# 查看内存使用
free -h

# 创建交换空间（如果物理内存不足）
sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 永久启用
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```
